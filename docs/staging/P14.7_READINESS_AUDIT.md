## 2. S-1 and F-1

### F-1 (original definition: P7 QA report)

- **Where it is defined:** `docs/benchmarks/diagnostics/20261029T084111Z-full-role-feature-ai-benchmark/ENARA_FULL_FEATURE_ROLE_QA_REPORT.md`, finding table. Restated in `ENARA_P7_QA_REPORT_REVISED_SCOPE.md` and carried forward in `20261029T090418Z-p8-p1-fixes/ENARA_P8_P1_FIXES_REPORT.md`.
  > F-1 | P2 | `GET /api/ingestion/status/:eventId` returns **500** in staging: it queries Postgres, which Option A doesn't configure … Return 503 `INGESTION_UNAVAILABLE` when Postgres isn't configured.
- **Implementation:**
  - `routes/ingestion.routes.ts:74-98` calls `getIngestionJobByEventId()` → `getPostgresPool()`, which throws `DATABASE_URL is required` (`config/postgres.ts:12-13`). The generic error handler turns that into 500.
  - The engine poll (`pollEngineStatus`) is after it, so it is never reached.
- **Tests:** `backend/test/p7RoleMatrix.test.ts:121-123` lists it as a known finding (`KNOWN` regex), so the sweep tolerates it. No test asserts 503.
- **Live evidence (P14.6, 19:19Z):** 500 `INTERNAL_ERROR` as the workspace admin; 401 unauthenticated.
- **Recommendation: optional improvement, not a safety issue.**
  - Return 503 `INGESTION_UNAVAILABLE` when `config.databaseUrl` is unset.
  - Replace the `KNOWN` exemption with an assertion.
  - It blocks **neither** the first controlled AI test **nor** a wider pilot: no paid path is reachable, and ingestion isn't used on staging.

### S-1 (definition: P14.5 finding, renamed in P14.6)

- **Where it is defined:**
  - First raised as "F-1 (session, medium)" in `docs/staging/P14.5_STAGING_SMOKE_TEST_REPORT.md` (summary and §5). That was a label collision with P7's F-1.
  - Renamed **S-1** in `docs/staging/P14.6_AI_TEST_READINESS_REPORT.md` §8.
  - Meaning: **there is no server-side logout or token revocation; a bearer token stays valid until its `exp`.**
- **Implementation:**
  - `routes/auth.routes.ts` has no logout route.
  - `auth/jwt.ts` verifies a stateless HS256 token with no token version or denylist. The lifetime is `JWT_EXPIRES_IN || "1h"` (`config/env.ts:361`); it's unset on staging, so 3,600 s (measured).
  - **Mitigation already present:** `middleware/auth.middleware.ts` re-reads the user on every request, so `status: 'disabled'` or a role change takes effect at once.
  - The SPA keeps the token in `localStorage` and clears it on a 401. CSP `script-src 'self'` limits XSS theft.
- **Tests:** none for logout. `p7RoleMatrix` "rejects disabled accounts outright" covers revocation by status.
- **Live evidence (P14.5/P14.6):** `POST /api/auth/logout` → 404; the token still works afterwards.
- **Recommendation:**
  - **Not mandatory for the first controlled AI test.** That test uses synthetic accounts only, the window is short, and an operator can disable a compromised account at once.
  - **Mandatory before a wider pilot with real users:** add a per-user `tokenVersion` (bumped on logout and password change, checked in `authMiddleware`) plus a logout route.
  - Optionally shorten `JWT_EXPIRES_IN`. This is a security control, so it needs its own approval.

### 3.2 Background jobs

`GET /api/cron/daily` (`routes/cron.routes.ts:22-45`) runs:
- grading sweep (**`ai_grading`**);
- curriculum-file processing;
- learning intelligence;
- avatar usage;
- the stale-reservation sweep;
- document scans and retention;
- speaking transcripts;
- reminders;
- the Monday weekly summaries.

Every AI step goes through the gateway, so the test cap applies.

**GAP-2:** `sendReminders` and `sendWeeklySummaries` **build AI-written content before attempting email** (`reminderService.ts:109-121`, `classSummaryService.ts:130-139`). Email cannot send on staging, so a cron call during the window could spend on messages nobody receives. **Mitigating factor:** these use `trackAiCall`, which passes **no price bound**, so under the test cap they are **refused** unless the school has a reservation ceiling configured for `anthropic:reminder_email` / `anthropic:weekly_summary`. The cron's **grading sweep** (`ai_grading`, bounded) **would** spend, within the cap.
- The route requires `Bearer CRON_SECRET`; there is no Vercel schedule.
- **Requirement (G20):** an attestation that no external scheduler calls it during the window.
- Optional fix: skip AI content when email is disabled.
