**Main findings:**
1. **F-1 (session, medium): there is no logout or token revocation on the server.**
   - Auth is a bearer JWT (HS256, 1 h lifetime) returned in the login body and kept in the browser's `localStorage`. `POST /api/auth/logout` does not exist (404), and a token keeps working until it expires.
   - **Mitigations already in place:** role, school and account status are re-read from the database on every request, so a disabled user or a changed role takes effect at once. CSP `script-src 'self'` reduces XSS exposure of `localStorage`.
2. **F-2 (readiness, low; known since P13):** `/ready` reports `postgres: ok` because `DATABASE_URL` is absent and `NODE_ENV` is not production (`app.ts:176-188`). It is not proof of a database.
3. **F-3 (coverage):** the student, no-access, second-tenant and class-boundary tests are **BLOCKED**. They need approved synthetic fixtures and a cleanup plan.
