## 2. What the app supports (from the deployed source)

| Need | Mechanism | Creatable via API | Deletable via API |
|---|---|---|---|
| Institution (+ its first admin + an API key) | `POST /api/integrations/institutions` (ENARA admin). The id is generated; the password and key are returned once | Yes | **No** institution delete; the API key can be **revoked** (`POST /api/integrations/api-keys/:id/revoke`) |
| User (any role, chosen password) | `POST /api/auth/users` (ENARA admin; `institutionId` in the body). A student user automatically gets a linked `Student` record | Yes | **No** user delete or disable route |
| Batch | `POST /api/batches` (school admin) | Yes | **Yes** (`DELETE /api/batches/:id`, hard delete, school-scoped) |
| Student record | auto-created with the student user, or `POST /api/students` | Yes | **Yes** (`DELETE /api/students/:id`) |
| Class (course instance; `instructorIds`, `studentIds`) | `POST /api/course-instances`, `POST /api/course-instances/:id/students` | Yes | **Yes** (`DELETE /api/course-instances/:id`, `DELETE …/students/:studentId`) |
| Curriculum | `POST /api/curriculums` | Yes | **Yes** (`DELETE /api/curriculums/:id`, school admin) |

- **Side effects of these routes:** none of them calls AI, email, ingestion or a queue. They are plain database writes (checked in the source).
- **Teacher class scope** is enforced through `instructorIds` on teacher read routes:
  - `/api/assignments/classes`
  - `/api/teaching/classes/:classId/roster`
  - `/api/teaching/students/:studentId/profile`
  - `/api/teacher/attendance`
  - grading lists
- **Unsupported, and the consequence:**
  - **There is no API to delete or disable users or institutions**, so those records can only be removed by an operator in Atlas (§5).
  - **There is no logout or revocation route (F-1)**, so revocation by logout cannot be tested.
  - Revocation by disabling an account works in code (status is re-read on every request), but disabling needs an operator database change.

## 6. Secrets handling

- Fixture passwords are generated locally (`secrets.token_urlsafe(24)`). The Tenant B admin password comes from the create response. All are written only to `scratchpad/secret/p146_creds.json` (0600) and never printed.
- The Tenant B API key is never printed or stored: it is revoked by its `apiKeyInfo.id` and the value is discarded.
- Tokens stay in process memory.
- Output and reports hold statuses, codes, counts, booleans and fixture numbers only. Before reporting, I scan the outputs for every password, token and email (as in P14.5).
