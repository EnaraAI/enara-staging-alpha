# Language engine v2 (14 Nov 2026)

Four changes from the system deep-dive (`research/deep-learning-simulation-v2/reports/ENARA_SYSTEM_DEEP_DIVE.md`). **All default OFF.** Enable with `ENARA_ENGINE_V2="wrongAnswer,belief,memory,cache"` (or `all` for those four; `arbitration` must be named: `all,arbitration`). Nothing here has been shown to improve learning yet: it must beat the plain AI tutor in a pre-registered experiment before it is switched on anywhere.

| Switch | What it changes | Evidence it works as built |
|---|---|---|
| `wrongAnswer` | The "teach the rule after a missed attempt" step used to depend on an answer-key verdict that can only be "correct" or empty, so it never ran for wrong answers. It now triggers from the recorded previous verdict (INCORRECT/PARTIAL) when the new answer also misses the key, also for tutor-written follow-up tasks. New wording says "if this new answer is right, confirm it and do not teach". | `test/engineV2.test.ts`: through the real engine, the second wrong attempt gets the rule only with the switch on; a first attempt never does. |
| `belief` | The hidden assessment line may carry `belief=<mistaken idea>` (3–8 words, sanitised). The learning state merges the same idea across items; a repeated idea gets a "scope rule + contrast example + apply it" instruction, and a standing "never call a mistaken idea fine / a fair point" line. | Parsing, merging, finalize-only-on-failure and prompt tests. |
| `memory` | Cross-session profile now stores mistaken ideas (short text, no learner answers), whether each is resolved, spaced reviews (3, 7, 14 days after resolution), and which explanation style preceded independent success. The next session's prompt lists open and due items and, at the first message, asks for one short unaided check. New `GET /api/me/tutor/reviews/due` (empty unless on; own learner only). Profile writes are now optimistic (version check + retry), so overlapping chat and voice turns no longer overwrite each other. | Pure-logic tests, plus a real-route test: belief stored, shown to the next session with the opening review, listed as due, another learner sees nothing, two concurrent writes both persist. |
| `cache` | The same language instructions split into a part that is identical every turn of a lesson (facts, lesson spec, level rules, grounding, marker format), placed early with the cache breakpoint, and a per-turn part (moves, state, history lines, length) placed last. Chat and voice both use it. | Measured on a real 3-turn lesson (Opus 5.5): without the switch `cache_read = 0` on every call (inputs 2,741 / 3,779 / 4,077 tokens). With it: turn 1 writes 1,803 tokens to cache; turns 2 and 3 read 1,803 from cache (fresh input 1,887 / 2,097). At list prices that is about 45% less input cost per turn after the first and about 29% over three turns; output cost is unchanged. |

| `arbitration` (named only; **not** part of `all`) | Settles the clash between the teaching-plan layer (23 methods: decides *how* to explain) and the language engine (decides *what may be revealed and when*). The plan text said "if methods disagree, follow the teaching method above" while the engine said its support level "takes precedence". With the switch on: one order of authority is stated in the language prompt (answer-hiding and support level first, then the plan's method, then base style); the contradictory plan line is replaced for language lessons; and when the plan calls for explicit instruction (direct instruction or worked example, chosen for emerging learners) the engine may give a two-sentence rule and a modelled example built from words in no lesson exercise before the first try, never the exercise's answer or target form. | 5 new tests. Real probe, emerging learner on GR-07 (plan: direct instruction + worked example): without the switch the tutor just set the exercise (the plan was effectively ignored); with it the tutor gave a one-line rule, a modelled example unrelated to the exercise, then the exercise, with no answer shown. |

| `keyMatch` (named only; **not** part of `all`) | The answer key treats contractions as their full forms on both sides ("She doesn't go" = "She does not go"). Ambiguous `'s` and `'d` are left to the tutor, and wrong answers still do not match. | 2 tests. Closes part of the "exact-string only" gap; equivalent answers inside longer sentences are still not matched on purpose (could credit a wrong answer). |

**Caching mechanics measured:** the model caches from about 1,100 tokens (probed at 1.1k, 2.2k, 3.3k and 4.9k tokens). ENARA's previous single breakpoint covered a prefix below that, so it never hit.

**Defaults and safety.** With all switches off the prompt and behaviour are unchanged; the existing language, avatar-link, ablation and research-flag suites pass (159 tests including 13 new). The answer-hiding guards, try-first rules and English-only rule are untouched.

**Known limits / not done.**
- No evidence yet about learning effects (Experiment 4's null warns against expecting large gains from prompt changes alone).
- The model's own "CORRECT" self-grade is still trusted (no independent check yet); answer-key matching is still exact-string.
- The repository has no student-data-erasure routine, so `learner_language_profiles` (old and new fields) is not covered by one; this needs an owner decision.
- Reading/writing/functional-language kinds, the reading guard exemption and the ped-v2 vs language-engine arbitration are unchanged.

## Added 13 Nov 2026 (default OFF, named-only: not part of `all`)
- `closing` — production-capable version of the research closing recap. From the learner's 5th message (or when every success criterion has been shown) the prompt asks for a two-line rule recap and "Tell me the rule in your own words". The engine appends that ask itself if the model leaves it out (`applyReplyGuards`), so the ask no longer depends on the model remembering it.
- `selfCheck` — independent check on the tutor's own CORRECT grade (deep-dive gap G3). For closed items (not open tasks), if the learner's answer contains none of the item's `targetForms` and the answer key did not confirm it, credit is held back (`AMBIGUOUS`, no criteria, same item, flag `self_grade_unverified`). It can only withhold credit, never give it. Known cost: a valid alternative answer without a target form gets no credit that turn.
- The wrong-answer teaching fix (G1) is the existing `wrongAnswer` switch.
Tests: `backend/test/engineV2Closing.test.ts` (6). Effect on learning or on rater scores: **not yet measured**.
- `clarity` — (default off, named-only) when the learner is stuck (2+ hint turns or attempts on the item, recurring error, asks why or for a hint, or the rule-teaching stage), the prompt asks for plain words, one idea per sentence, the rule in one sentence first, then a right/wrong contrast with other words, then ask the learner to apply it; never the corrected form of the open task. Test in `engineV2Closing.test.ts`. Learning effect not yet measured.
- `hints` — (default off, named-only) when the tutor's last two replies were hint-shaped questions, the next reply must change form (rule in one plain sentence + right/wrong contrast, then ask to try again); also makes the `clarity` explanation appear after the first recorded miss instead of the second.
- **Bug fixes found in the 18-triplet agent study (apply to `closing`/`clarity` when those are on):** (1) the closing recap now happens once: after the tutor has asked for the rule in own words, the rule check takes over (before, the ask was repeated every turn from the 5th on, producing "recap loops"); (2) `clarity` fired after every evaluated answer because `errorRecurrence` is the string `unknown` (truthy); it now needs `repeated`. The 18-triplet results for B therefore reflect the buggy versions.

## Added 14 Nov 2026: clarity switches (default off, named-only; see `docs/ENARA_METHODS_AND_CLARITY.md`)
- `ruleFirst` — first exposure to a rule, inside whichever of the 23 methods is selected (it never changes method selection). On the reply to the learner's first attempt, hint request, "I don't know" or "why" on an item whose success criterion has not been introduced this session, the tutor states the rule in ONE plain sentence of 20 words or fewer, in the style of the selected method (worked example / direct instruction → through a worked example; analogy → through a comparison; otherwise the right/wrong pair), gives one right and one wrong example made of words from no lesson exercise, then asks the learner to apply it to a new item. For that reply only it replaces the "no rule before the first try" instruction and the hint-level rule limits; it never allows the answer or target form of the open item. Introduced rules are recorded as `rulesIntroduced` in the stored turn evidence and read back from history, so each rule is introduced once per session. The turn that only presents an exercise is never affected (the first try stays unassisted).
- `shortRecap` — replaces the closing "tell me the rule in your own words" ask: the rule in one line (≤ 20 words), then "Now write one new example of your own." Once per session; the engine appends the ask if the model leaves it out; afterwards an example check (`EXAMPLE_CHECK`) takes over, like the rule check after the old ask.
- `socraticOff` — **research only, ignored when `NODE_ENV=production`**: removes the two "no rule before the first try" instructions (exercise presentation; hint level 1 may state the rule in general terms) and nothing else; the correct form, the choice and the target form stay hidden.
Tests: `backend/test/engineV2Clarity.test.ts` (12). Effect on rater scores or learning: not yet measured.
