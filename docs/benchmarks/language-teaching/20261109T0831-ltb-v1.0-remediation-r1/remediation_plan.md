# Remediation plan: LTB v1.0 findings → `ltc-v1-r1`

All four failures trace to one file: the deterministic signal and move layer of the Phase 1 engine, `backend/src/services/languageTeachingContext.ts`. The tutor route, the controller, `ped-v2` and the model call were not at fault, and none of them changed. Each root cause below was verified both in the code and in the baseline traces (`../20261109T-ltb-v1.0/raw_results.jsonl`).

| # | Baseline failure | Root cause (verified) | Code change (`ltc-v1-r1`) | Tests |
|---|---|---|---|---|
| F1 | T13: full answer given on request, 9/9 major over-helping | `selectLanguageMoves`: `answerRequest && !hintsOnly → answer_with_reasoning` (old LTC-D6). In 9/9 traces the engine chose it and the model followed | The engine counts the learner's attempts on the current task chain (`attemptsOnCurrentTask`, derived from session history). With 0 attempts, an answer request picks `scaffold_hint` (reason `answer_requested_before_attempt`), with prompt text "Don't give the answer yet … one try". After ≥1 attempt it picks `answer_with_reasoning` ("they have already tried"). `hints_only` behaviour is unchanged (never the answer). New moves: `distinct_example` (example asked for while a task is open) and `restate_task`. On a 2nd+ wrong attempt the tutor may show the model answer | R1 block (12 tests), T13 replay (9/9), route test |
| F2 | Learner answers not recognised (23 answer-feedback misses) | `answeringCheck` required `?` in the last 300 characters of the tutor's previous reply (`endsWithCheck`). Tutors close exercises with instructions or gap frames. It fired on 48/90 later turns | `taskInvitation()` classifies the previous reply's close as `question`, `instruction` or `sentence_frame`. `classifyLearnerResponse()` separates `answer` from `answer_request`, `hint_request`, `dont_know`, `repeat_request`, `example_request`, `help_request`, `confusion`, `greeting`, `off_topic`, `other_request` and `no_pending_task`. Pending state is derived per turn from the session's own stored history: no new persistence, it can't cross sessions or learners, and it is deterministic on retry | R2 block (16 tests), replay of all 23 traces (23/23), route test for cross-session and cross-learner leaks |
| F3 | No age adaptation; 25/30 overruns in child cases | The prompt had no length or step target. The age band was only "adult" (school setting) or unknown. The controller never passes a grade, so children and teens were both "unknown" | Configurable `lengthTarget(ageBand, CEFR step)` (target and max words, `basis` recorded), one step per reply, no tables or headings, a register line per CEFR step (A1/A2/B1) and per age band (adult vs age unknown). **Child/teen distinction: BLOCKED.** ENARA has no approved age source beyond the school's adult-learners flag, and the brief forbids inferring age from grade. Age-unknown learners therefore get a conservative, school-safe and non-childish target | R3 block (4 tests), route test (no grade or DOB in the payload) |
| F4 | T11: off-topic redirect 1/9 | No off-topic signal existed. T11 turns got generic lesson moves that invited long mini-lessons | `offTopicKind()` returns `unrelated` (another subject's homework, or a finished deliverable for them, when phrased as a request), `adjacent` (a language question about any topic, e.g. "how do I say fractions in English") or `social`. On `unrelated`, `redirect_to_lesson` is chosen and `activate_prior_knowledge`, `short_explanation`, `fade_support` and `independent_practice` are suppressed. With no lesson, the redirect still doesn't do the task | R4 block (13 tests), T11 replay (9/9 redirected; 0 false flags across the other 111 cases) |

## What did not change

- The tutor route, controller, `ped-v2`, model or effort, `max_tokens`, gateway, metering, budgets, feature flags, roles and tenant scoping.
- Grading, assessment, analytics, voice and avatar, and non-language courses (the engine returns null for them, as before).
- The context block tag stays `<language_teaching_context version="ltc-v1">`. The revision `ltc-v1-r1` appears inside the block and in `meta.languageTurn.policyRevision`.

## Risks

- **Pattern-based signals.** The repo has no structured task-state source, so detection uses regexes. They can misfire on unusual phrasings; the tests cover several unseen ones. Hidden prompt instructions are the backstop.
- **Hint-first adds a turn** for learners who genuinely want the answer.
- **Length targets** may cut useful detail for some B1 or adult requests. They are targets, not truncation.
- **Benchmark tuning (disclosed).** Two detection tweaks (the help phrasings "how to say" and "does it mean", and example requests with no open task) were prompted by the B1 T01/T02/T09 baseline traces. The engine-move check (`expected_move_any`) is therefore partly tuned to these cases and should be read as an engine regression check, not an independent measure.
