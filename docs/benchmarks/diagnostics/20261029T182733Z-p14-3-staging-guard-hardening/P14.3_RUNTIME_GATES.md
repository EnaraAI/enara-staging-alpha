# P14.3: runtime gates (operator checklist)

**For:** the authorized operator. **When:** after the P14.2+P14.3 change is reviewed, committed, pushed and deployed. None of this was done in P14.3.

**How to report:** for each item, give `#n: VERIFIED | FAILED | UNKNOWN — evidence type, date`.
- Never paste secret values, connection strings or tokens.
- Report names, booleans, ids and counts only.

**Owner decisions applied:**
- **Infrastructure:** the Atlas database/cluster and the R2 storage are confirmed purpose-built for staging. This checklist does not re-investigate that. It only checks that the app uses them.
- **Spend:** live spend is capped at USD $5 total, and only after every gate below passes and is separately authorized.

## Gate 6: test window and emergency stop

| # | Step | Detail | Classification |
|---|---|---|---|
| 6.1 | Open | Gates 1–5 pass, plus written authorization. One approved change sets `ANTHROPIC_API_KEY`, `AI_TEST_SPEND_CAP_USD`, `AI_TEST_SPEND_ID` and `AI_PAUSED=false` → redeploy → record the new deployment id → re-run 1.1–1.5 and 5.4 | OPERATOR_ACTION_REQUIRED |
| 6.2 | Stop (emergency) | **Remove `ANTHROPIC_API_KEY` and redeploy.** This is the only switch that stops every feature including grading. `AI_PAUSED=true` stops non-grading only. Fastest stop that needs no redeploy: revoke the key in the Anthropic console | OPERATOR_ACTION_REQUIRED |
| 6.3 | Automatic stop | Cap reached → every call refused with `AI_TEST_SPEND_CAP` (429), grading included. Raising the cap needs new approval and a new id | VERIFIED_EXISTING (code) |
| 6.4 | Close | Remove the key, revoke it in the console, redeploy; confirm the provider console shows no further usage; reconcile the provider console, `usage_ledger` sum and `test_spend:p14` counter (amounts internal) | OPERATOR_ACTION_REQUIRED |
| 6.5 | Re-attest after any change | Any variable change creates a new effective configuration: repeat gates 1–2 against the new deployment id | OPERATOR_ACTION_REQUIRED |
