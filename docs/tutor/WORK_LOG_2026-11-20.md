## 3. Learner memory (plan: `docs/tutor/LEARNER_MEMORY_PLAN.md` on tutor-kids-pack)
**Rules for all phases:**
- written by code from graded evidence or school / parent / learner screens; the model only reads a short brief;
- fixed codes, no free text, no question or answer text;
- deleted with the learner (`studentErasure`); summaries and habits expire after 13 months;
- every phase has its own `ENARA_ENGINE_V2` switch, named only and off by default.

| Phase | Switch | What it does | Where |
|---|---|---|---|
| **1. Errors to work on** | `workOn` | Wrong items on **released** assignment attempts become errors (objective + error type). They are used only when the assessment is over (closed, past its date, or no attempts left), released, and no attempt is in progress. The next session opens with at most 3 (2 for children), ordered recurring, then prerequisites, then most recent; the tutor reteaches with new items, and sentences containing the exam's questions are removed. Two independent rights in later sessions resolve an error; a wrong answer reopens it. Teachers and admins have a panel with Dismiss. | **PR #34: merged 14:07, deployed to lms-test 14:13, `workOn` on (lms-test only)** |
| **2. Session memory** | `sessionMemory` | A code-built summary per quiet session (right/wrong, answered items, most common error, open exercise, next step). The next session's first reply gets a "last session" line ("Start here: …"). Lesson items answered in earlier sessions are never offered again as "next". A per-turn **learner brief** of at most 8 lines (errors, last session, profile, habits). | **PR #35, deployed to lms-test; `sessionMemory` on (lms-test only)** |
| **3. Profile and habits** | `learnerProfile` | First language (school admin), interests (up to 5, chosen by the learner, a parent or an admin) and accommodations (school admin). The model gets only the effect, for example "typed answers are fine", never the reason. A nightly study-habits rollup (sessions, minutes, time of day, breaks); a learner back after 7+ days gets a short review first. | **PR #35, deployed to lms-test; switch on (lms-test only)** |

## 10. Errors from Moodle's own quizzes (owner "You build it")
Built from plan v2 (`MOODLE_QUIZ_IMPORT_PLAN.md`). Setup for a school: `MOODLE_QUIZ_IMPORT_NOTES.md`. Switch: `moodleQuiz` (named only; needs `workOn`), on for lms-test only. Each school must still save a token and switch the import on.

**How it works**
1. **Token.** The school's Moodle admin creates a web service with only 3 read functions and gives ENARA its token.
   - The school admin pastes it in **LMS connections → the connection → "Errors to work on from Moodle quizzes"**.
   - It is stored encrypted with the LMS key, is write-only (never returned or logged), and is checked once on save.
   - The code can call no other Moodle function.
2. **Mapping.** The admin picks an ENARA objective for each Moodle quiz (optionally per question slot). Only this school's approved objectives are accepted.
3. **Import** (nightly, or "Import now"). For each mapped quiz and each linked learner:
   - the gate must be open: the quiz is closed or the learner has no attempts left, review of right/wrong is allowed then, the attempt is finished and none is in progress;
   - then each wrong, partly right or skipped question becomes an error to work on (code `moodle_wrong`), and right answers count toward resolving;
   - each attempt is imported once.
   - Ids only: no question text, answer or Moodle name is stored.
4. **Tutor.** These errors reach the tutor like the others. Because Moodle gives right/wrong and not the mistake, the tutor knows the objective, not the exact error.

**What changed in LMS-track files** (small hooks; everything else is in new files):
- one router line in `admin/routes.ts`;

- the model list and a migration (`2026-11-30-lms-moodle-quiz`, new collections only);
- the card on the LMS connections page.
